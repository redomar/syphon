## Key decisions & reasons

- **Rewrite = v1.0.0.** The branch name already implied it; the per-epic versions (v0.3–v0.9) in EPICS.md were relabelled as historical planning labels. Landing badge and `package.json` now say 1.0.0.
- **Two budget models kept, converging at E6.** E3 "Budgets" (category tracking vs actuals) and PR #8's model (income vs bills forecast) answer different questions. Renamed the latter to **Cashflow** to de-conflict the nav; `migrateBillsToRecurring` starts the fold-in of bills to the unified recurring model.
- **Linear history, one commit per epic** on a single branch, each gated on typecheck + full vitest + production build + a real-browser E2E flow.
- **recharts removed** (E7 charts are now dependency-free CSS/SVG). recharts 3.x amplified a render loop and was flaky under React 19; the charts are simple enough not to need it.
- **Pushed as a new branch (`v1.0.0-epics`) + PR #9 rather than pushing `v1.0.0-rewrite` directly**, because that would have advanced the shared branch irreversibly and silently auto-closed PR #8. A checkpoint branch **`checkpoint/pre-v1-epics`** pins the pre-epics upstream state (`02c13c3`) — `git reset --hard checkpoint/pre-v1-epics` returns to it.

## Notable bug fixed

**Reports page "Maximum update depth exceeded".** Root cause was *not* recharts: the report queries derived `startDate`/`endDate` from `new Date()` on every render, so `useQuery` args changed each render → Convex re-subscribed → re-render, infinitely. Fixed by memoizing the date range on the range selector. (Two red herrings en route: a stale Vite optimize-dep cache serving 504s, and orphaned dev servers on ports 5173–5175 serving old code.)
